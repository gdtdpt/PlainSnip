## 1. PixPin 行为观察结论（设计基准）

从官方文档提炼的交互模型（与 ShareX 自动滚动式完全不同）：

1. **入口**：截图 → 框选（只框会滚的内容）→ 工具条「长截图」按钮 / `L` 键
2. **进入长截图态**：选区外变暗；选区旁出现长截图工具栏；屏幕一侧出现**拼接预览**
3. **手动滚动为主**：用户自己滚轮滚目标内容，软件**实时截帧拼接**——这是 PixPin 与 ShareX 的本质差异
4. **自动滚动**（`A`）：鼠标在选区内时才滚，速度按选区大小自适应，再按一次停
5. **拼接预览 + 绿框**：绿框 = 当前选区画面在长图中的位置；绿框消失 = 当前画面超出已拼接范围，往回滚
6. **匹配失败不重来**：提示「滚动过快/切窗/动态内容」，往回滚到绿框处继续即可
7. **裁剪**：`J` 裁当前画面之前、`K` 裁之后；「滚动方向改变时自动裁剪」可选
8. **完成去向**：复制并关闭 / 贴图 / 保存 / 编辑 / OCR / `Esc` 放弃
9. **到底**：前后画面相同即到底（PixPin 文档隐含）；超长有提示与上限

## 2. 范围（M4 交付 / 不交付）

**交付**：
- 截图工具条新增「长截图」按钮（快捷键 `L`），选区确定后进入长截图态
- 纵向拼接（向下滚动）；手动滚轮为主 + `A` 自动滚动辅助
- 拼接预览窗（实时 + 绿框）
- 匹配失败提示与回滚恢复；到底自动停 / 提示
- 完成去向：复制 / 保存 / 贴图（复用 M2）/ `Esc` 放弃
- `--selftest` 覆盖拼接算法（合成滚动帧序列验证）

**不交付（留档后补）**：
- 横向拼接（算法对称，UI 需一套方向态，确认纵向稳定后快速加）
- 裁剪 `J/K` 与「方向改变自动裁剪」（拼接成功后裁顶/裁底可作 M4 收尾补充项，见 §7 开放问题）
- UIA ScrollPattern / WM_VSCROLL 定向驱动（见 §5 决策 D5）
- 超长截图分段保存

## 3. 状态机

```
Selected ──L──▶ LongShotEnter ──▶ LongShotIdle ──(滚动/自动滚动)──▶ LongShotCapturing
                                                    │
                匹配失败◀──(帧无法拼接)──▶ 正常拼接循环
                    │
                    └──(往回滚，帧重新可拼接)──▶ 回到 Capturing
任意时刻：Esc / 完成按钮 ──▶ LongShotDone（复制/保存/贴图）或 退出回 Selected
```

- 长截图态内 M1b 预选、M3 标注、放大镜全部关闭（放大镜无快照可放大）
- 「匹配失败」不是终态：保持已拼结果与上次绿框，等用户回滚
- Esc 语义 = 退出长截图，回 Selected 态（保留选区与快照）；再 Esc 才取消整个截图（沿用 M3 肌肉记忆）

## 4. 关键难点：遮罩窗形态转换与实时抓屏

长截图基于**实时屏幕**而非 M1a 冻结快照，必须解决两件事：

**① 选区内不能有任何自身窗口像素**（否则被拍进帧）：

- 遮罩窗调 `SetWindowRgn` 为「屏幕矩形 − 选区矩形」的环形区域：选区内**零渲染、零命中**，
  滚轮事件天然直达目标窗口，`BitBlt` 抓选区矩形干净无遮挡
- 备选方案（4 块独立暗罩窗）否决：多窗管理复杂、跨屏选区难处理

**② 工具条与预览窗必须避开选区矩形**：

- 二者均为独立置顶窗，摆在选区外侧（复用 M1a 工具条的翻转/夹取避让逻辑）
- 均不与选区矩形相交 ⇒ 不会进入帧；PixPin「自动排除工具栏」是其内部黑科技，
  我们靠布局避让达到同样效果（这也是 PixPin 文档让用户「只框滚动内容」的原因）

选区边缘保留描边（绿框 = 预览中的位置指示，选区本身用现有描边样式）。

## 5. 关键设计决策（2026-11-25 用户逐项确认）

| # | 决策 | 定案 | 理由 |
|---|---|---|---|
| D1 | 交互范式 | ✅ **PixPin 式手动滚动为主**，`A` 为辅助 | ShareX 全自动式对非标准控件兼容差；手动滚动天然适配一切可滚内容 |
| D2 | 方向 | ✅ M4 仅**纵向** | 横向 UI/交互多一套；算法对称，后补成本低 |
| D3 | 截帧时机 | **100ms 定时截帧 + 与上帧比对去重**（相同则不拼接） | 滚轮全局钩子复杂且杀毒软件敏感；定时法简单可靠，10fps 足够 |
| D4 | 到底检测 | 新帧与上帧**完全相同**（连续 2 次采样）即判定到底 | ShareX 同思路；自动滚动下到底自动停，手动下提示「已到底」 |
| D5 | 自动滚动驱动 | ✅ **SendInput 滚轮注入**（光标必须在选区内），不做 UIA/WM_VSCROLL | 滚轮注入对 Chrome/微信/Excel 等通用性最好；UIA 分支留 v1.5 增强，偏离 §5.4 原优先级 |
| D6 | 匹配失败恢复 | 失败仅提示，**不破坏已拼结果**；回滚后下一帧自动重新接上 | PixPin 核心体验；算法上在结果底部窗口内搜索可自然支持 |
| D7 | 长度上限 | 高度上限 **16384px**，达到即提示并停止 | 1920 宽 × 16384 高 ≈ 126MB 单份位图；拼接瞬时双份峰值 ~250MB，自用可接受 |
| D8 | 裁剪 J/K | ✅ M4 先**不做**，拼接结果直接进去向 | 拼接完成态裁剪是独立小功能，可 M4 收尾补（§7） |

## 6. 拼接算法（自行实现，借鉴 ShareX 思路）

**帧**：选区矩形物理像素 `BitBlt`（32bpp），宽度固定 = 选区宽。

**行比较**：按 stride 做连续字节序列比较（`Span.SequenceEqual` 等价逻辑）；
左右各忽略 `max(50, W/20)`（≤ W/3）避开滚动条/边缘；底部忽略边（任务栏、浮动提示等）
采用 ShareX 的 AutoIgnoreBottomEdge 思路：两帧自底向上找第一行差异确定忽略行数，
并与历史最佳忽略值取 max（防止边缘偶发抖动来回横跳）。

**对齐**：在**已拼结果底部**（深度 ≤ 帧高/2）自底向上为当前帧每一行找**最长连续相同行序列**，
取最优 `matchIndex`（当前帧内行号）。成功 ⇒ 追加高度 = 帧高 − matchIndex − 1；
失败 ⇒ 走 D6。本次失败但历史有更优匹配时降级为「部分成功」（ShareX bestGuess 思路）。

**绿框**：当前选区画面顶部在结果中的 y = resultH − frameH + matchIndex。

**结果位图增长**：每轮拼接新建更大 Bitmap 并重绘（ShareX 做法，O(n²) 累计但 n 有限可接受）；
若实测卡顿再改预分配策略（§7 开放问题）。

**单元测试**（进 `--selftest`）：程序合成一张 3 屏高「长页」（含纯色页眉模拟固定区），
切成带 1/3 重叠的帧序列喂给拼接器，断言：输出与原长图逐行相等；
再加一帧跳变帧断言「失败路径」与回滚恢复。

## 7. 开放问题（实现期决定）

- 结果位图增长策略：重建 vs 预分配（先重建，真机有卡顿再换）
- 匹配失败提示的呈现方式（预览窗内红字 vs 工具条状态区）
- 裁剪 J/K 是否在 M4 收尾补（取决于纵向主链路真机验收顺利程度）

## 8. 模块划分

| 模块 | 新/旧 | 职责 |
|---|---|---|
| `ScrollCaptureSession` | 新 | 长截图状态机 + 截帧节拍 + **拼接算法**（纯逻辑，无 UI 依赖，供 selftest） |
| `ScrollPreviewForm` | 新 | 侧边预览窗（结果缩放 + 绿框 + 失败/到底提示） |
| `CaptureOverlayForm` | 扩展 | 长截图模式转换（Rgn、关预选/标注/放大镜、长截图工具条、键位） |
| `ScreenCapture` | 复用 | 选区矩形帧捕获 |
| `PinManager` / 保存/复制 | 复用 | 完成去向 |

键位：`L` 进入/停止拼接、`A` 自动滚动、`Ctrl+C` 复制并关闭、`Ctrl+S` 保存、
贴图按钮、`Esc` 退出长截图（回 Selected）。

## 9. 真机验收清单（对照 PixPin）

1. Chrome 网页：含固定导航栏页面，长图无重复导航、无错位
2. 微信聊天记录：深色/浅色、图片混排
3. Excel 长表格：横向滚动条不出现在结果中
4. 滚动过快 → 匹配失败提示 → 回滚恢复续拼
5. 到底：自动滚动自动停 / 手动提示已到底
6. 达到 16384px 上限提示并停止
7. 三去向（复制/保存/贴图）产物正确
8. Esc 退出回 Selected，选区可继续标注（快照模式完好）

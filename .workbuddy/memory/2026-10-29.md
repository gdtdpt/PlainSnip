## 踩坑记录（重要，跨里程碑适用）

1. **PMV2 下纯代码 WinForms 窗体的 DPI 布局坑**（主屏 200% 真机踩过）：
   - GDI 字体随窗口 DPI **自动**放大（9pt 在 200% 屏 = 24px 字形步进），但代码里写的控件/窗体尺寸是物理像素、**不**缩放 → 大字塞进小布局，标签被截断（视觉上像“字符串被截”其实是渲染裁剪）。
   - `AutoScaleMode = Dpi` / `Font` 对纯代码创建的窗体**不生效**（AutoScaleDimensions 手动设 96,96 也没用）。
   - 解法：`AutoScaleMode = None` + 所有布局尺寸统一过 `S(logical) = logical * DeviceDpi / 96`（SettingsForm.cs 已实现）。M1 遮罩/放大镜/工具条照此办理。
   - CJK Label 的 `AutoSize` 测量偏小也会截断 → 用固定宽度 + MiddleLeft。
2. `shot_window.py` 输出的 PNG 是 RGB (colortype 2) 非 RGBA，手写解码按 bpp=3。
3. 排查 UI 截断用「红底诊断 + 像素级测量」（zlib 解 PNG 反过滤 + 扫描线）闭环，别靠猜。
4. WinExe `--selftest` 输出：AttachConsole 在重定向管道下不可靠 → 同时落 `%TEMP%\PlainSnip-selftest.log`（覆盖写）。

## M1a 修复：双击复制失效（f06fbaa）
- 根因：WinForms 双击序列 Down/Up/Down/DoubleClick/Up，第二次 Down 先 BeginMove 把状态切成 Moving，DoubleClick 里 `State == Selected` 永不成立。
- 修法：DoubleClick 处理器容忍 Moving，先 EndInteraction 收敛回 Selected 再 CopySelection。
- 验证：构建+selftest 25 项 PASS；端到端脚本模拟双击后剪贴板确认有位图（IsClipboardFormatAvailable CF_DIB）。
- 经验：⭐ 依赖鼠标事件顺序的交互（双击=快捷动作 + 单击=开始拖动）都有这个模式坑——**DoubleClick 处理器的状态断言必须考虑第二次 Down 已改变状态**。

## 正式应用图标（虚线选框+剪刀）
- tools/make_icon.ps1 生成 App.ico：GDI+ 4x 超采样绘制，16/24/32/48 DIB + 256 PNG 条目；16px 用实线框保可辨识。
- csproj ApplicationIcon（exe 文件图标）+ EmbeddedResource（运行时）共用同一 ico；IconFactory 按 SmallIconSize（DPI 感知）加载。
- 坑①：csc CS7065 "Unable to read beyond the end of the stream"——PowerShell 函数返回 byte[] 被管道展开成 object[]，BinaryWriter.Write 重载绑定错乱，ICO 目录声明尺寸与实际数据不符。修法：`return ,($arr)` 防展开 + 写入时 `[byte[]]` 强转。
- 坑②：多尺寸 ICO 全用 PNG 条目有 .NET Icon 解析器兼容风险——小尺寸走经典 DIB 最稳。

## M1b 修复：悬停高亮不跟随鼠标（节流初始化溢出）
- 用户反馈：多窗口时高亮卡在 F1 进入时的初始预选，不跟随鼠标（放大镜正常，因其不走节流门槛）。
- 根因：`_lastHoverTick = int.MinValue`，`now - int.MinValue` 整数溢出回绕为负 → `>= 50` 恒假 → MouseMove 永不触发检测。
- 修法：uint 差值比较（(uint)(now - last) >= 50），同时免疫 TickCount 24.9 天回绕。
- 验证：--settings 窗（独立进程）+ --hover 双点位端到端：光标在设置窗上高亮 840×400，移出后切换 2736×1800 大窗口。
- 经验：⭐ 节流时间戳不要初始化为 int.MinValue/long.MinValue 再做减法——溢出回绕让条件恒假；用无符号差值或首帧特判。
- 教训：改完代码必须重建再跑冒烟（本轮第一轮"高亮没变"实为旧 exe，浪费一轮验证）。

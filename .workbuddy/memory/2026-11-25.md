## M4 滚动截图设计定稿（docs/m4-scroll-design.md）
- 研究输入：ShareX ScrollingCaptureManager.cs（**GPL v3，只参考思路禁抄代码**）+ PixPin 官方长截图文档（行为基准）。
- 核心结论：PixPin 与 ShareX 是两种范式——PixPin 手动滚动为主+实时拼接+绿框预览+失败回滚续拼；ShareX 全自动注入滚动。
- 用户逐项确认 D1 手动为主 / D2 仅纵向 / D5 SendInput 滚轮注入（作废 §5.4 原三段式 UIA→WM_VSCROLL→键盘）/ D8 裁剪 J/K 不做。
- 关键难点：实时抓屏下选区内不能有自身窗口像素 → 遮罩窗 SetWindowRgn 挖环形洞（零渲染零命中，滚轮直达目标窗）。
- 拼接算法（自实现）：行级字节比较 + 左右/底部忽略边 + 结果底部深度≤帧高/2 找最长相同行；失败不破坏结果，回滚续拼；到底=前后帧相同。
- selftest 计划：合成 3 屏长页切帧喂拼接器，断言逐行相等 + 失败路径。
- 实施顺序建议：ScrollCaptureSession（拼接算法+selftest）→ 遮罩窗长截图模式转换 → 预览窗/工具条 → 自动滚动。

## M4 第 1 步完成：ScrollCaptureSession 拼接核心（commit 进行中）
- 新文件 src/PlainSnip/ScrollCaptureSession.cs：ProcessFrame 帧处理（FirstFrame/Appended/NoChange/MatchFailed/HeightLimit）+ AlignFrame 对齐搜索 + GetRows/LockBits 行缓冲。
- 关键实现决策：**删掉 ShareX 的 bestGuess**（本次失败沿用历史参数强行追加会把无关帧贴进结果），失败即 MatchFailed 提示回滚（符合 D6）；_bestIgnoreBottom 保留（防边缘抖动横跳）。
- 对齐语义（ShareX 思路，已逐行推导验证）：frame 行 matchIndex 与 result 底部 rectBottom=resultH-ignoreBottom-1 对齐，向上连续相同；新内容 = frame[matchIndex+1..]，贴在 resultH-ignoreBottom 处；到底帧 appended=0。
- 回滚续拼条件：用户回滚后继续向下滚，帧底部越过 rectBottom 且帧顶 p ≥ rectBottom-帧高+1（重叠 ≥1 行）即自然接上；搜索深度 = matchLimit(帧高/2)，回滚过深会匹配失败（符合 PixPin「往回滚一点」）。
- 比较窗口 bug 修正：regionRows 必须 = matchLimit + ignoreBottom + 1（覆盖搜索全深度），否则回滚深度被截断。
- selftest 7 用例全过：主链 10 帧→1200px 逐行相等 / 重复帧 NoChange / 黑帧 MatchFailed / 回滚续拼→1300 / 底部噪声 500px。
- 🔴 测试断言教训：合成帧数×步长与断言高度对不上（10 帧×100=1200 不是 1300）；比较基准图高度要与阶段结果匹配。
- UI 层（下一步）：遮罩窗 SetWindowRgn 挖洞 + 100ms 截帧 Timer + ScrollPreviewForm + 长截图工具条（L/A/Ctrl+C/Ctrl+S/Esc）。
